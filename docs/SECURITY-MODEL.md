# Security model

Guard trusts its host, policy/authority/evidence providers, Broker callback, durable store, clock and protected platform. The Agent is an untrusted requester. An Agent must not load Guard with a self-selected policy and then claim that result is an authorization from a trusted service. Authenticate it at Admission and derive actor identity from that session.

Guard checks an exact action/resource/scope, required independently supplied evidence, authority and freshness. Limited Blocking explicitly opts in. It binds a one-use in-process permit to the complete protected operation digest; changing an operation after admission is rejected. The Broker callback is trusted code and must execute exactly the reviewed mutation. A digest is not permission to invent a different payload. The GitHub mapping binds numeric repository, branch, paths, revisions and mutation fingerprint.

The credential belongs solely to Broker execution. No credential transport, storage or provisioning API is supplied to Agent. The package does not establish OS isolation: a physically separate dedicated host, distinct Admission/Broker service accounts, internal-only Broker IPC and restricted credential permissions require deployment verification. Real credential isolation remains unverified here. A compromised Broker/root administrator can cross this trust boundary. Remote platform restrictions remain necessary defense in depth.

On missing authority/evidence, invalid binding, unavailable store or uncertain execution, do not fall back to direct execution. DENIED and UNRESOLVED never invoke Broker through the tested enforcement path. Persist dispatch intent before invocation. A crash or ambiguous execution result requires reconciliation; preventing a retry can sacrifice availability. This is not a general exactly-once distributed transaction guarantee. Admission outage means callers have no permitted alternate write path. Broker outage fails closed. `disable()` is local process state: operators must persist deployment disablement separately.

Evidence is a local hash chain with operation metadata, authority/evidence capsules where available, decisions and results. Verification replays available admission capsules and checks binding/lifecycle consistency. Missing/unresolved authority cannot be reconstructed as a verified decision. Hash chains do not defeat trusted-storage rollback, replacement of the entire chain or a malicious host; no external notarization is claimed. Retain backups and access control under operator policy.

Known bypasses: another write credential, another remote write route, caller-controlled authority, caller-controlled executor, host compromise and insufficient remote branch rules. Guard cannot stop writes that never traverse its enforcement boundary. Shadow intentionally leaves the existing write path untouched. No universal prompt-injection defense or content-safety classifier is claimed.
